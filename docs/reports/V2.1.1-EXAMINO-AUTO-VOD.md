# v2.1.1 – Examino Auto VOD / Source “Loading…” (2.1.0 field)

**Date:** 18 Nov 2026  
**Branch:** `cursor/v211-examino-auto-vod-ccd4` (stacked on v2.1.0 / PR #18). Do not merge until signed off.

## Field evidence

- Overlay MatchTimer **2.1.0** on Examino: Auto VOD ON, Source stuck on **Loading…**, stream stays near live (~−32s). Extension OFF: gear → Source → VOD works.
- Xeatre black screen (separate, next after this): console shows adapter + host-chrome hide installed; VIDEOJS “hdmi-video already initialised”; video area fully black. **Not started here** — hide path is `omt-host-xeatre` / different selectors; not the same CSS override bug as Examino gear.

## Root cause

When host chrome hide was scoped under `html.omt-host-examino.omt-hud-on`, the Auto VOD / scrape path’s temporary gear reveal lost the specificity war:

| Rule | Specificity (approx) |
| --- | --- |
| Hide: `html.omt-host-examino.omt-hud-on .setting-holder` / `.omt-examino-native-hidden` | wins |
| Old override: `.setting-holder.omt-settings-temp-visible` (1.2.0-era) | loses |

`ensureOpSettingsOpen()` adds `omt-settings-temp-visible` and clicks the gear. With the gear still `display:none` / `pointer-events:none` / `max-height:0`, the settings panel never opens → `scrapeOpSourceOptions` returns `loading: true` → Source fill shows **Loading…** and Auto VOD never applies VOD. Manual gear (extension OFF) never needs that override, so VOD still works.

**Named culprit:** scoped Examino hide CSS without a matching scoped `omt-settings-temp-visible` undo (also missing undo for sticky `omt-examino-native-hidden` on `.setting-holder`).

## Fix

1. Raise temp-visible + raised-panel CSS in `content.css` and `injectExaminoHideCSS()` so they beat `.setting-holder` and `.omt-examino-native-hidden` under `html.omt-host-examino.omt-hud-on` (including `max-height` / `overflow`).
2. `fillSourceSelect`: on scrape `loading` with empty options, keep **DVR / VOD** selectable instead of sticking on Loading….
