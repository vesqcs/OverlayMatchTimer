# v1.7.0 — Kickoff sync (short report)

## How it works

Kickoff sync is an **optional** Customize setting (collapsed section, toggle **off by default**). When off, the sync module is a no-op: the page does not ask the bridge to talk to the network, and the service worker refuses fetch if somehow messaged while disabled.

When on, the user pastes their own Supabase **project URL** and **anon key** (saved only in `chrome.storage.local`). Chrome requests optional host access to that project origin at enable time. Setting or nudging kick-off publishes a row keyed by match room (page URL / Examino id, or an optional Room id). Colleagues with the same project + room pull updates every few seconds.

Code lives in `Overlay-chrome-extension/src/sync/` (MAIN hooks), `bridge.js` (relay), and `background.js` (REST). SQL for the table + RLS is in `supabase/migrations/` — **not** applied by the extension.

## What the owner needs to set up

1. Create a dedicated Supabase project (recommended).
2. Run `supabase/migrations/20261113120000_kickoff_sync.sql` in that project.
3. Copy Project URL + anon key into Customize → Kickoff sync; turn the toggle on; accept the host permission.
4. Use the same match page or the same Room id across machines.
5. Never put the service-role key in the extension; never commit keys to git.

Details: `supabase/SETUP.md`.

## Risks

- Shared anon key + open RLS policies mean anyone with the key can read/write all `kickoff_sync` rows in that project — treat it as a private team room.
- Wrong Room id / different URLs → people do not see each other’s kickoffs.
- Enabling sync grants the extension network access to the configured origin; leaving it off keeps store review surface smaller (optional permission unused).
