# v1.7.5 — Timeline bookmarks, click-to-toggle, tooltips, auto-hide

## Timeline

1. **No period colour bands** — scrubber fill is a single `--omt-scrub` colour for the whole match (never live-red / never period-tinted).
2. **Bookmarks** at each period start (1st Half / 2nd Half / ET1 / ET2): Lucide bookmark pin above the track; subtle at rest, clear + label on timeline hover; click seeks to that kick-off.
3. **Hover tip** shows `period · match clock` (mm:ss as the on-video clock would), not raw video time. Before kick-off: `Pre-match`. Redesign-only (`matchClockAtVideoTime`); original clock hooks untouched.
4. Keeps v1.7.4 optimistic fill on scrub.

## Click-to-toggle play/pause (regression)

**Cause:** The original `OverlayMatchTimer.html` dashboard bound `vid.addEventListener('click', …)` (plus dblclick fullscreen with undo). When the extension local player shipped (v1.5.0), only file/DnD was ported — **that click handler was never wired** for `site.id === 'local'` (or InPlay/Xeatre). Examino already had `installExaminoClickToToggle`. `#omt-root` correctly uses `pointer-events: none`, so the miss was missing JS, not an overlay swallowing clicks.

**Fix:** Restore the HTML-dashboard mechanism in `wire.js` for non-Examino sites (local / InPlay / Xeatre-ready): capture-phase click on `<video>` → `togglePlay()` (exclusive so host players cannot double-toggle); dblclick → fullscreen + reverse the single-click toggle. Controls/clock/timeline stay `pointer-events: auto` and never hit `e.target === vid`. Guard also accepts `srcObject` (InPlay mock / MediaStream).

## Tooltips

`.glass-panel` was `overflow: hidden`, which clipped top-row `data-tip` bubbles (Volume, etc.). Panel is now `overflow: visible`; tips use higher z-index; left/right clusters stay inset; when the card is near the player top, tips flip below (`omt-tips-flip-below`).

More chevron: tip is **More controls** when collapsed and **Less controls** when expanded.

## Auto-hide (regression from v1.7.4)

**Cause:** v1.7.4 grew `#omt-timeline-bar` with `padding-top: 30px` so the period tip fit inside the bar, and hover keep-alive (`pointerOverOmtUi`) tracked the **whole bar**. Resting the mouse in the lower video area sat on that padded shell → idle fade never armed. Eye toggle / timer body were fine; the hit box was wrong.

**Fix (redesign only):**
- Shorten the timeline padding (v1.7.2-sized); tip escapes above via absolute positioning.
- Timeline shell `pointer-events: none`; track + times re-enable hits.
- Hover keep-alive binds to track/times only, not the full-width shell.
- Hidden chrome still disables child hits via `omt-chrome-hidden`.

With Auto hide **ON**: fade after the original 2.5s idle; mouse move on the video restores. With **OFF**: chrome stays visible. **H** still hides/shows completely.
