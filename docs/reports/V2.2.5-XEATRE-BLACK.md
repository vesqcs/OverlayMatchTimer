# v2.2.5 – Xeatre black screen (hdmi-video)

**Date:** 18 Nov 2026  
**Branch:** `cursor/v225-xeatre-black-ccd4` (stacked on v2.2.4 / PR #26). Do not merge until signed off.  
**Scope:** Xeatre adapter only. InPlay frozen. Examino untouched.

## Field clues (2.1.0+)

1. `[OMT] Xeatre host chrome hide installed`
2. `VIDEOJS WARN: Player "hdmi-video" is already initialised`
3. Player area fully black

## Root cause

2.1.0 hide CSS blanked **`.vjs-poster`** (and other non-chrome layers) while `#omt-root` was appended **inside** the Video.js shell (`#hdmi-video` / `.video-js`). Host observers that re-call `videojs('hdmi-video')` then warn and leave the tech unpainted → poster gone + black frame.

Pre-2.1.0 only hid `#ControlBar.overlay-*` and never touched the picture layer.

## Fix (Xeatre only)

- Hide **chrome leaves only**: `.vjs-control-bar`, big-play, `#ControlBar` overlays, known button IDs, `.xeatre-control-panel`
- Do **not** hide `.vjs-poster` / spinner / text-track / modal
- Force-visible CSS on `#hdmi-video` / `video.vjs-tech`
- HUD `findAnchor` = **parent of** the VJS shell (sibling mount) — never append into the player tree
- Never call `videojs()`; never reparent `<video>`
- `[OMT-DEBUG][xeatre]` JSON-string logs (video + ancestor paint chain, player init count)

## E2E

- Fixture: `hdmi-video` shell + hostile MutationObserver that re-inits on childList inside the shell
- `xeatre-hdmi-video-painted-no-reinit`, `xeatre-no-already-initialised-warning` (+ existing chrome-hidden test)

## E2E result

**188/188 pass** (adds `xeatre-hdmi-video-painted-no-reinit`, `xeatre-no-already-initialised-warning`).

Examino / InPlay / shared boot+ui modules: **unchanged** vs 2.2.4 tip.
